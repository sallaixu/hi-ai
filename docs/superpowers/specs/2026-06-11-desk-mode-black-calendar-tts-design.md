# 桌面模式黑底万年历与 TTS 展示设计

**日期**: 2026-06-11  
**状态**: 待审查  
**范围**: Android 桌面模式界面布局调整

## 1. 概述

### 1.1 目标

重新设计 hiai Android 项目的桌面模式界面，使其更适合横屏设备展示，并满足以下需求：

- 桌面模式整体使用**纯黑背景**，尽量减少 OLED 发光区域，达到省电目的。
- 在**待唤醒状态**下显示**万年历**样式信息：数字时钟、年月日、星期。
- 在**唤醒后**切换为助手展示状态，呈现助手相关信息。
- 在 **TTS 播放过程中**，将当前 TTS 文本显示在界面上，方便用户直接阅读。
- 当 WebSocket 断开时，桌面模式自动退回到待唤醒界面。

### 1.2 设计原则

- **极简**：待机界面只显示必要信息，避免视觉噪音。
- **省电**：背景始终保持纯黑，尽量减少高亮区域面积。
- **清晰**：时钟和日期必须足够大，远距离可读。
- **状态明确**：用户能一眼看出当前是待唤醒、已连接还是正在播放 TTS。

## 2. 状态定义

桌面模式由下列状态驱动：

1. **待唤醒状态**
   - 条件：WebSocket 断开，或当前没有有效助手会话。
   - 展示：大时钟 + 年月日 + 星期 + 底部轻量状态栏。

2. **助手状态**
   - 条件：WebSocket 已连接，且服务处于唤醒后的交互阶段。
   - 展示：助手相关信息，例如当前状态、语音识别结果、对话提示等。

3. **TTS 展示状态**
   - 条件：收到服务端 `tts` 消息，且状态为 `start` / `sentence_start`。
   - 展示：当前 TTS 文本占据主视觉区域，突出当前正在朗读的内容。

4. **异常状态**
   - 条件：发生错误但仍处于桌面模式。
   - 展示：尽量保留黑底风格，仅在底部或小区域提示错误。

## 3. 界面布局设计

### 3.1 横屏总体布局

桌面模式采用横屏全屏布局，分为三层：

- **主区域**：显示时间、日期、助手内容或 TTS 文本。
- **底部状态栏**：显示当前模式、连接状态、低功耗提示等。
- **空白区域**：保留大面积纯黑背景，不绘制多余装饰。

### 3.2 待唤醒界面

待唤醒界面采用居中排版：

- 第一行：超大数字时钟，例如 `09:41`。
- 第二行：年月日，例如 `2026 / 06 / 11`。
- 第三行：星期，例如 `星期四`。
- 底部状态栏：显示 `待唤醒`、`低功耗模式`、`连接中断` 等轻量状态。

要求：
- 时间必须是最醒目的元素。
- 日期和星期字号明显小于时间，但仍需易读。
- 只使用浅色文字，不使用亮色背景块。

### 3.3 助手展示界面

唤醒后进入助手展示界面：

- 主区域显示当前对话状态。
- 若已收到 STT，显示用户输入文本。
- 若正在播放 TTS，显示当前 TTS 文本。
- 若无具体内容，可显示简短状态提示，例如“正在聆听”或“正在回复”。

### 3.4 TTS 文本展示

TTS 文本展示规则：

- 收到 `tts.start` 时切换到 TTS 展示布局。
- 收到 `tts.sentence_start` 时更新当前句子文本。
- TTS 播放期间，文本显示在主视觉区域，优先级高于普通状态提示。
- TTS 结束后保留最后一句，或返回助手状态视图，具体行为由现有状态流转决定。

### 3.5 底部状态栏

底部状态栏保持低存在感，只显示最必要的信息：

- 当前模式：待唤醒 / 助手 / 正在说话
- 连接状态：已连接 / 已断开
- 低功耗提示：仅在待唤醒状态显示

状态栏不得喧宾夺主，不得影响主视觉层级。

## 4. 状态切换规则

### 4.1 WebSocket 断开

当 WebSocket 断开时：

- 桌面模式自动切换到待唤醒界面。
- 清空助手内容区，避免保留过期对话。
- 保留时间和日期显示，继续作为待机主视觉。

### 4.2 WebSocket 重连成功

当 WebSocket 重新连接并恢复会话时：

- 桌面模式切换回助手展示界面。
- 若已存在 TTS 内容，则优先展示当前 TTS 文本。
- 若当前没有 TTS 内容，则展示助手状态提示。

### 4.3 唤醒后进入助手展示

唤醒成功后：

- 退出待唤醒万年历界面。
- 显示助手相关信息。
- 保持纯黑背景不变，仅调整内容层级和文字。

## 5. 与现有状态的关系

当前应用已有桌面模式入口与服务状态流转。该设计要求桌面模式界面与服务状态联动，但不改变整体服务行为：

- `DeskModeScreen` 继续作为桌面模式入口。
- `VoiceAssistantService` 的状态变化驱动 UI 切换。
- 网络连接状态应作为桌面模式界面切换的重要依据。

## 6. 视觉约束

- 背景必须是纯黑色 `#000000` 或等效纯黑。
- 不使用渐变背景，不使用大面积发光装饰。
- 所有正文保持高对比浅色文字。
- 间距充足，避免拥挤。
- 文字层级清楚：时间 > 日期 > 星期 > 状态提示。

## 7. 验收标准

设计完成后，应满足以下标准：

1. 桌面模式背景为纯黑。
2. 断开连接时，界面清晰显示时钟、年月日和星期。
3. 唤醒后，界面切换到助手相关内容。
4. TTS 播放期间，界面能显示当前 TTS 文本。
5. 界面在横屏下排版合理，不出现拥挤或遮挡。
6. 待唤醒界面保持省电、极简、易读。

## 8. 非目标

本次设计不包含：

- 新的语音交互协议设计
- 新的唤醒词算法设计
- 动画特效或复杂粒子背景
- 自定义主题切换功能
- 多页面导航重构

## 9. 待确认项

- 待唤醒界面是否需要显示秒数：当前方案不显示秒数，仅显示时:分。
- 助手界面是否需要保留历史对话列表：当前方案仅显示当前交互的主信息，不强制展示完整历史。
